# Working style

*How Himanshu wants work delivered on the LiD app — stay on the asked scope, commit when told*

Himanshu interrupted a long detour into repairing PDF text-extraction artefacts
with: *"lets move on next step, lets verify the pdfs later if the answers are
correct or not. currently we have the dataset so lets use it to make the app."*

**Why:** the tangent was real but minor — cosmetic spacing that never affected an
answer — and it stalled the thing he actually wanted, a working app. He is
building a product, and prefers visible progress on the product over polishing
data he has already accepted as good enough.

**How to apply:** deliver the asked scope and stop. Note a side issue in one
sentence and move on rather than fixing it mid-task; if it matters, offer it as a
next step. He says "commit this" after each chunk he is happy with, so keep the
working tree in a committable state and do not commit unprompted. He reviews on a
real device, so the fastest useful loop is: change, typecheck, confirm the bundle
builds, tell him to reload.

He also asks for design work to be shown before it is built — the UI direction was
reviewed as a published artifact mockup, then ported to React Native once approved.
